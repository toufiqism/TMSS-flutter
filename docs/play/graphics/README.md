# Store graphics

Everything Play asks for as an image, generated from the repo rather than hand-exported,
so a re-run reproduces the same files.

| File | Spec | Generated by |
|---|---|---|
| `play-icon-512.png` | 512×512, opaque, square corners | `tool/store/generate_store_graphics.py` |
| `play-feature-1024x500.png` | 1024×500, opaque | same |
| `screenshots/*.png` | six 1440×2560 (9:16) frames | `tool/store/generate_store_screenshots.py` |
| `screenshots/raw/*.png` | 1344×2992 device captures | the emulator, by hand — see below |

```bash
python3 tool/store/generate_store_graphics.py      # icon + feature graphic
python3 tool/store/generate_store_screenshots.py   # frames, from screenshots/raw/
```

Both print the dimensions of what they wrote; the screenshot script also prints Play's
ratio check per file. Requires `brew install resvg` and `pip3 install pillow`.

## The screenshots contain no real data

Every name, address, vehicle plate, phone number and requisition in `screenshots/raw/`
is invented. They are captures of the real app talking to `tool/store/mock_api_server.py`
— a local stand-in for the TMS API that serves twelve synthetic requisitions and a
four-person employee directory.

This is deliberate and not a shortcut. The live account holds a real employee's name, ID
and phone number and real business records, none of which may be published to a store
listing; it is also full of `Probe Test` rows left over from API contract probing, which
would make the listing look broken. Capturing against the mock solves both at once, and
needs no reviewer account provisioned in production first.

## Recapturing the raw frames

Wanted whenever the UI changes.

```bash
# 1. serve the synthetic API
python3 tool/store/mock_api_server.py 8099

# 2. build a profile APK pointed at it (10.0.2.2 is the host, seen from the emulator).
#    Profile, not release: the main manifest sets usesCleartextTraffic="false", and only
#    the debug and profile manifests override it. Profile is otherwise release-like —
#    AOT, no debug banner — so the pixels match what ships.
flutter build apk --profile --target-platform android-arm64 \
    --dart-define=TMS_BASE_URL=http://10.0.2.2:8099

# 3. install on a Pixel 9 Pro XL emulator (1344×2992) and turn animations off
adb install -r build/app/outputs/flutter-apk/app-profile.apk
for s in window_animation_scale transition_animation_scale animator_duration_scale; do
  adb shell settings put global $s 0
done

# 4. sign in — the mock accepts any credentials
adb shell input tap 445 1237 && adb shell input text 'nusrat.jahan@btracsolutions.com'
adb shell input keyevent 61     # TAB to the password field
adb shell input text 'demo1234'
adb shell input keyevent 66     # ENTER submits

# 5. capture each screen
adb exec-out screencap -p > docs/play/graphics/screenshots/raw/01-dashboard.png
```

Two things that cost time the first time round:

- **Tap coordinates move when the keyboard opens.** The Sign In screen collapses its
  header while the IME is up, so a coordinate read off a keyboard-closed screenshot lands
  on the wrong field. Move between fields with `keyevent 61` (TAB) instead of tapping.
- **`input text` needs its spaces escaped** (`'Banani\ Head\ Office'`) and its `#`
  quoted, or the shell eats them.

Restore the emulator afterwards: set the three animation scales back to `1` and reinstall
the release build, so a profile APK pointed at localhost is not left sitting on the device.

## Promo video

```bash
python3 tool/store/generate_promo_video.py     # -> tracgo-promo-1080p.mp4
```

1920×1080, 32 s, built from the same `screenshots/raw/` captures: an intro card, six
scenes that each pair a caption with a slowly pushing-in phone, and an outro card,
cross-faded. Frames are piped into ffmpeg as raw RGB rather than written out — 972 frames
of 1080p PNG would be a couple of gigabytes of scratch.

The push-in is centred rather than a vertical pan. A pan was the first attempt and read as
a bug: by mid-scene it had scrolled each screen's app bar out of view.

Upload notes, listing copy and the YouTube settings that Play actually depends on are in
`../youtube.md`.
